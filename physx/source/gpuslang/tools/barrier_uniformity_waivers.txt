# ===========================================================================
# Waivers for check_barrier_uniformity.py
#
# Format, one per line, four fields separated by `|`:
#
#     <shader file> | <pass> | <guard text> | <why it is block-uniform>
#
# `pass` is scope, escape or call -- the same word the report prints.  The
# guard text is matched after whitespace normalisation, so copy it from the
# report verbatim.
#
# A WAIVER IS A CLAIM SOMEBODY CHECKED, NOT A WAY TO SILENCE THE TOOL.  The
# fourth field must say why the value is the same in every thread that reaches
# the barrier, in terms someone can re-derive from the shader.  "Looks fine" is
# not a proof; "the last write before the loop is a warp-max broadcast" is.
#
# If a genuinely divergent barrier ever gets a waiver, the tool goes quiet on
# exactly the bug it exists to find -- so a waiver whose proof no longer holds
# must be deleted, not updated.
# ===========================================================================

# --- psPrimCollide.slang ---------------------------------------------------
# `range` really is per-lane where it is first computed (`endIndex - startIndex`
# over that lane's own cell), and the checker's taint is FLOW-INSENSITIVE, so it
# keeps that verdict.  But the last write before the loop replaces it with the
# WARP MAXIMUM -- `sRange[lane] = range; barrier; range = max over sRange[0..31]`
# -- so every lane enters the loop with the same bound and runs the same number
# of iterations.  The file's own header (line 61) names this as the invariant
# that keeps the per-round ballot and barriers group-uniform.  Deleting the
# warp-max would make all three sites real.
psPrimCollide.slang | scope | for (uint ind = 0; ind < range; ++ind) | last write before the loop is the warp-max broadcast of range (sRange[lane] -> max over 0..31), so the trip count is warp-uniform; see the file header, line 61
psPrimCollide.slang | call  | for (uint ind = 0; ind < range; ++ind) | same warp-max broadcast: ballot32 is reached with the same trip count in every lane

# --- npTriTriFind.slang (P9.83b-8, 3/n) ------------------------------------
# The fixture's copy of the mesh-mesh kernel's inner loop (convexMeshMidphase.cu:1064),
# tested on the REGISTER copy of the refinement count exactly as the P9.83b-8 refine
# map derived for the CUDA.  Both terms are block-uniform: numTrianglesToSubdividePerThread
# is read from gTtfNumSubdivide by every thread AFTER the barrier that follows thread 0's
# write (and is 0 or the seed read after the prologue barrier), and startIndex is
# written by ttfFindInterestingTriangles from gSdfOffset, which every thread reads after
# the function's final barrier.  round and maxRounds are uniform by construction.
npTriTriFind.slang | scope | while ((startIndex < nbTriangles || numTrianglesToSubdividePerThread > 0u) && round < maxRounds) | numTrianglesToSubdividePerThread is every thread's read of gTtfNumSubdivide after the barrier that follows thread 0's publish; startIndex is every thread's read of gSdfOffset after ttfFindInterestingTriangles' final barrier -- the cu:1064 argument of the P9.83b-8 refine map
npTriTriFind.slang | call | while ((startIndex < nbTriangles || numTrianglesToSubdividePerThread > 0u) && round < maxRounds) | same loop, same two block-uniform reads: every thread calls the gather and addToRefinementBuffer the same number of times

# --- triTriCollisionBda.slang (P9.83b-8) ---------------------------------------
# The kernel's own cu:1064 loop, the same shape as the gather fixture's above.
# numTrianglesToSubdividePerThread is every thread's read of gTtfNumSubdivide after
# the :1204 barrier that follows thread 0's publish of the refinement count; i is
# every thread's read of gSdfOffset after ttfFindInterestingTriangles' final barrier
# (the function returns it through its inout startIndex); nbTriangles is the pass's
# mesh triangle count, read from pairIdx-indexed memory.  The checker demotes both to
# WARP because they come out of collectives that take tid.
triTriCollisionBda.slang | scope | while (i < nbTriangles || numTrianglesToSubdividePerThread > 0u) | numTrianglesToSubdividePerThread is every thread's read of gTtfNumSubdivide after the :1204 barrier that follows thread 0's publish; i is every thread's read of gSdfOffset after the gather's final barrier -- the cu:1064 argument of the P9.83b-8 refine map, as for npTriTriFind
triTriCollisionBda.slang | call | while (i < nbTriangles || numTrianglesToSubdividePerThread > 0u) | same loop, same two block-uniform reads: every thread calls the gather, addToRefinementBuffer, the count and the assignment the same number of times

# --- aggregateBda.slang (P9.92) ----------------------------------------------
# boxPruningProjection (aggregate.cu:767): the pair loop runs to totalCount, which is
# `warpShfl(lane, inclusiveSum, 31u)` -- every lane writes gsLane[lane], the barrier
# follows, and every lane reads gsLane[31].  The workgroup is ONE warp of 32 lanes
# (numthreads(32,1,1), the virtual-warp scheme in the file header), so that read is the
# same value in every thread of the group.  The checker taints the call's result by its
# `lane` argument; the CUDA's own loop bound is the same __shfl_sync broadcast.
aggregateBda.slang | call | for (uint b = 0u; b < totalCount; b += WARP) | totalCount is warpShfl(lane, inclusiveSum, 31u): every lane reads gsLane[31] after the barrier that follows every lane's write, and the workgroup is the one 32-lane warp, so warpBallot and warpShfl are reached the same number of times in every thread
