# push_block_known.txt -- the P9.78b ratchet.
#
# Each line is an entry point that never reads one of the arguments the engine
# pushes to it:
#
#     <cuda kernel name>   <index>@<offset>+<size>:<slang field>;...   # <why>
#
# THE WHY COLUMN IS MEASURED, NOT ASSUMED.  All 204 unread arguments were read
# against the engine's CUDA, one by one:
#
#     dead-upstream  152   the CUDA kernel does not use the parameter either
#     deferred        51   the shader's own header documents the omission
#     suspect          1   claimed a real gap; refuted (see below)
#
# The three recurring causes, with the evidence that settles each:
#
#   DEAD UPSTREAM.  removeContactManagers_Stage1..4 take ONE parameter in CUDA
#     (pairManagement.cu:45-64) while the host builds a TWO-argument pack and
#     fires it at all five stages (PxgNarrowphaseCore.cpp:8527-8546) -- the
#     third instance in this codebase of "one host pack, several kernel
#     signatures", after the particle solves (P9.76) and the softbody pair
#     (P9.76b).  `materials` is threaded through four particle contact-gen
#     kernels and their whole helper chain (cudaParticleSystem.cu:1189-1679)
#     and never dereferenced once.  `toleranceLength` accounts for 40 of the
#     204 on its own, upstream typo `tolerenceLength` included.
#   ABI PARITY.  boxBoxNphase.slang says it in the struct itself:
#     `float toleranceLength; // @132 (unused by this kernel, present for ABI
#     parity)`.
#   A DEFERRED BRANCH.  Articulations (14), cone limits, SDF, speculative CCD,
#     a dynamic-rigid reaction -- each documented in its shader's header.
#
# THE ONE SUSPECT, and what it was worth: sb_clothContactGenLaunch was claimed
# to drop the `stackSizeNeededOnDevice` atomicMax that softbodyPrimitives.cu
# :1648 writes unconditionally in its tail.  Refuted as a port gap -- the kernel
# is upstream-dead (`supportClothTriangleCollision = false`,
# PxgNarrowphaseCore.cpp:4529, with no other mention in the tree) and the LIVE
# sibling does implement the write (softBodyClothVertContactGenBda.slang:217).
# But the shader's STATED REASON was false, and it has been corrected: the tail
# guard is reachable, the kernel is simply dead.  A wrong reason reaching the
# right conclusion is the P9.76a shape.
#
# What the list is FOR is that the number stops being assumed.  The recorded
# SIGNATURE is checked, not just the name: a kernel that starts leaving a
# DIFFERENT argument unread is a regression the bare name would hide.  The list
# may SHRINK, never grow.
#

#
