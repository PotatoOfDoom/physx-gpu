# push_name_known.txt -- the P9.99 NAME-leg ratchet of tools/check_push_block.py.
#
#     blind <cuda kernel> <a@off/b@off;...>   # why, with the evidence
#     swap  <cuda kernel> <member>            # why (a NAME-SWAP that is not a swap) -- none
#
# A `blind` line names the swaps the checker cannot see at all: an exchange that changes no
# offset, trips no join rule (CUT/STRADDLE/F-SUBWORD/RUN-ON) and leaves the name leg silent,
# because neither name says which CUDA field it is.  The checker finds them by simulating
# every swap of
#   (a) two REACHED members of equal member size, whatever fields they cover -- a word over
#       a bool trades places with a PxU32 without any size changing;
#   (b) a REACHED and an UNREACHED member of equal size inside ONE row argument, the reach
#       moving with the member.  (Across arguments such a SHADER-side swap moves
#       push_block_known.txt's signature, which carries the unread argument's index and the
#       member name over it.)
#   (c) `cuda:x@off/y@off` -- two named CUDA fields of equal size, at least one under a
#       reached member, exchanged in the CUDA declaration (and the host pack with it): the
#       shader, its reach and every offset stay, so only the name of the reached member can
#       see it (check round, C1).  Not repeated when the two fields lie under the two
#       members of an (a)/(b) pair above; not simulated for two fields under ONE packed word
#       (the documented byte-order limitation).
# The signature is checked, not just the kernel: a kernel that turns blind on a DIFFERENT
# pair fails (MOVED).  The list may shrink, never grow; a stale line fails.  Every line below
# was settled by reading what the shader DOES with each member against the CUDA (P9.99).
# Where a (c) pair was a pure rename away from decidable, the shader member was renamed to
# the CUDA name instead (check round: numTests -> numWorkItems in the three midphase blocks,
# prepDesc -> prepareDesc in the four rigid attachment/contact prepare blocks,
# clothAppliedForces -> softBodyAppliedForces in cloth_particleContactPrepareLaunch; the
# .spv changed in those OpMemberName strings only).
#
# Positional names: one TwoPtrParams/ThreePtrParams struct serves kernels whose CUDA puts
# the aggregate desc first in some and the broadphase desc first in others, so no single
# pair of names can be right (do NOT rename p0/p1: real names would be wrong for half of
# the kernels and turn into true NAME-SWAP findings).  The cast at each use fixes the role:
