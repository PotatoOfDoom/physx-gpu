# engine_reachable_unmapped.txt -- the unmapped kernels the SIMULATION PIPELINE
# launches.  Read by tools/check_unmapped_reachability.py.
#
# THIS IS A RATCHET, not a permission slip.  A new engine-reachable unmapped kernel
# fails the check, and so does an entry left here after its port lands -- a stale
# allowlist is how a ratchet quietly stops ratcheting.  It may shrink; it may not grow.
#
# ---------------------------------------------------------------------------
# WHY THIS FILE EXISTS: "98 TO GO" WAS NEVER 98
# ---------------------------------------------------------------------------
# P9.65 set out to port isosurfaceExtraction.cu -- 34 unmapped kernels, the biggest
# single block left -- and asked the liveness question first.  The answer stopped the
# tranche: the isosurface extractors are created only through PxGetPhysicsGpu(),
# whose factory (physxgpu/src/PxgPhysXGpu.cpp) IS NOT COMPILED into this build, and
# the Vulkan bridge's PxGpuCreatePhysicsGpu() returns NULL.  No scene, and no
# application, can construct one here.
#
# Classifying all 98 the same way gives:
#
#     11  ORPHAN      nothing launches them even upstream (already in
#                     check_disabled_kernels.py's ORPHANED table)
#     58  STANDALONE  app-facing features -- isosurface (34), SDF builder (18),
#                     sparse-grid provider (9... see the tool), anisotropy (2),
#                     smoothed position (2) -- not constructible in this build
#     29  ENGINE      launched from the simulation pipeline: the list below
#
# So the remaining reachable work is 29 kernels, not 98.  Porting the 58 would move
# PXG_SLANG_KERNEL_MAPPED from 403 to 461 while moving what the port can DO by
# nothing, and no scene could observe a wrong answer from any of them.  That is
# manifest theatre, and this file is here so the distinction survives being
# rediscovered.
#
# ---------------------------------------------------------------------------
# THE 29, GROUPED BY LAUNCHING SUBSYSTEM
# ---------------------------------------------------------------------------
# PxgNarrowphaseCore.cpp (12) -- the largest coherent group and the most observable:
# convex-core collision against every geometry, sphere/trimesh, trimesh/plane,
# trimesh/heightfield, triangle-triangle, softbody/heightfield.  A scene can watch
# every one of these, which is what this project's method depends on.
# convexCoreClothmeshNphase_Kernel32 -- MAPPED in P9.74 (cvxCoreClothNpBda.spv).  The
# LAST of the five, and the third distinct shape among them: a midphase-pair consumer
# with no BVH traversal at all, a fixed 32x512 grid with a grid-stride loop, a triple
# `&&` vertex filter, and a contact write WITH barycentric.  Its 176-byte ABI row is
# shared with neither of the other two convex-core rows.  Observed by
# PXG_SCENE=clothcvxcore.
# convexCoreConvexNphase_Kernel -- mapped in P9.69c (cvxCoreCvxNpBda)
# convexCorePlaneNphase_Kernel -- MAPPED in P9.67c (cvxCorePlaneNpBda.spv), the
# first of the five.  PXG_SCENE=convexcoreplane went from final y=-73.807 to
# 0.5000, the cylinder's radius and the same number the capsule scene gives.
# convexCoreTetmeshNphase_Kernel32 -- MAPPED in P9.72 (cvxCoreTetNpBda.spv).  NOT a
# sibling of the trimesh kernel despite the name: nine arguments ending in an 80-byte
# PxgFEMContactWriter by value, no writeOutput, no patch accumulator.  Observed by
# PXG_SCENE=softbody PXG_SB_FLOOR=convexcore.
# convexCoreTrimeshNphase_Kernel32 -- MAPPED in P9.70c (cvxCoreTriNpBda.spv).  The
# third convexCore arm, and the one the `convexcoretrimesh` scene was written
# against BEFORE the kernel existed, so the red measurement is on record.
# evaluatePointDistancesSDFBatch -- MAPPED in P9.95 (sdfQueryBda.spv), DRIVEN by
# PXG_SCENE=sdfquery via PxDirectGPUAPI::evaluateSDFDistances, its only caller: a
# query the API launches on demand, never a simulation step, so no scene that only
# steps could have reached it.  Red measured first: unmapped, all 1112 live output
# slots stayed at the -999 poison and the call still returned true.
# sb_heightfieldContactGenLaunch -- MAPPED in P9.81 (softBodyHfContactGenBda.spv),
# and DRIVEN, by PXG_SB_FLOOR=heightfield -- the sixth floor of the softbody scene's
# floor matrix and the first (softbody, heightfield) pair this harness has ever built.
# Measured with the kernel skipped: the cube fell through to -49.8831 against 0.4893
# on the box floor and 0.4883 on the cooked mesh, all three at the same floor height.
# sphereTrimeshNarrowphase -- MAPPED in P9.66b (sphereTriNpBda.spv).  It was the
# only unmapped kernel in testSDKSphereTriMeshSATGpu's chain, and it carried two
# ordinary geometry pairs: sphere-vs-mesh and capsule-vs-mesh.
# triangleTriangleCollision -- MAPPED in P9.83b-8 (triTriCollisionBda.spv), the SDF
# mesh-mesh contact generator, driven by PXG_SCENE=sdfmesh (the raised shelf and the
# two stacked SDF boxes, which reach both SDF arms and both passes).
# trimeshHeightfieldNarrowphase -- STAYS ON THIS RATCHET, and NOT because it is work.
# It is UNREACHABLE, and this is a FIFTH kind of deadness, distinct from the four
# already on record (commented-out caller; never-constructed owner; #if 0 body; a
# host guard no scene raises):
#
#   *** A DISPATCH CASE FOR A BUCKET ID NO CLASSIFIER EVER PRODUCES. ***
#
# The kernel exists, its launcher exists, and PxgNphaseImplementationContext.cpp:225
# has a `case GPU_BUCKET_ID::eTriangleHeightfield:` that calls it.  Nothing reaches
# that case.  gTable[eTRIANGLEMESH][eHEIGHTFIELD] is cndCaseMeshHeightfield (:1319-
# 1329), which returns eFemClothHeightfield when side 0 is cloth and eFallback
# otherwise -- so a RIGID mesh against a heightfield goes to the CPU fallback, and
# the CPU table's slot for that pair is PxcInvalidContactPair.  Repo-wide the token
# eTriangleHeightfield appears in exactly three places: the enum (PxgNarrowphaseCore.h
# :117), that dispatch case, and one count variable (:609).  Never as a result.
#
# THE SECOND PIECE OF EVIDENCE, and the one that makes this more than a naming
# argument: its HOST LAUNCH PACK DOES NOT MATCH ITS OWN KERNEL.  The kernel declares
# (toleranceLength, cmInputs, cmOutputs, shapes, transformCache, contactDistance, ...)
# at trimeshCollision.cu:437-456; the pack at PxgNarrowphaseCore.cpp:1326-1344 passes
# (numTests, cmInputs, transformCache, contactDistance, gpuShapes, cmOutputs, ...).
# Slots 2..5 are a FOUR-WAY PERMUTATION of pointers.  Every one is 8 bytes, so the
# launch would not fault -- it would read the contact-manager outputs as a transform
# cache.  Its PLANE sibling, thirty lines earlier at :1236-1250, passes exactly the
# order its kernel declares, which is what identifies the heightfield pack as a
# mis-edited copy of it rather than a different convention.  It has never fired
# because the bucket is never populated.  Documented as an upstream bug candidate;
# NOT reported.
#
# Mapping this kernel would therefore move the manifest by one and move what the port
# can DO by nothing, and no scene could observe a wrong answer from it -- the same
# test this file applies to the 58 standalone kernels.  If upstream ever revives the
# bucket, the pack has to be settled before a port can be validated against it.
#
# It is LISTED rather than deleted for the reason sb_plasticDeformLaunch is listed:
# the checker's ENGINE test is "a .cpp outside gpuslang names the PxgKernelIds enum",
# which is TRUE here -- PxgNarrowphaseCore.cpp launches it -- so deleting the line
# makes the checker report it as un-ratcheted work.  A fifth kind of deadness with
# ONE instance does not justify teaching the checker a DEAD_BUCKET test; a second
# instance would, and the same standing rule already governs DEAD_OWNER.
trimeshHeightfieldNarrowphase

# PxgMemCopyDispatcher.cpp (1)
# copyUserData -- a FIFTH kind of unreachability, found by P9.79 and named here
# because no existing bucket covers it: its launch site
# (PxgMemCopyDispatcher::flushCommands) is compiled, but PxgMemCopyDispatcher is
# CONSTRUCTED NOWHERE -- not as a member, not as a local, not via PX_NEW.  The
# owner class is dead, so the call site can never run.
#
# check_unmapped_reachability.py cannot see this: its ENGINE test is a

# hand-verified argument is how a ratchet stops ratcheting -- but the measurement is
# recorded so the next tranche does not spend a day porting a kernel nothing runs.
# Turning this into a SIXTH checker bucket (DEAD_OWNER, re-derived per run like
# STANDALONE's three legs) is worth doing when a second instance shows up; one
